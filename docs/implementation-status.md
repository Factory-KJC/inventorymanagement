# 実装状況と次作業

最終確認日: 2026-08-29  
対象ブランチ: `develop/new_design`

この文書は、リポジトリの実装状況、設計との差分、既知の課題、次に着手する作業をまとめたものです。機能追加や検証の完了時に更新します。

## 1. 現在地

APIの基本機能とスマートフォンPWAの初期実装まで完了しています。ロードマップ上ではPhase 2を「実装完了・実機表示確認待ち」としていますが、MVP完了条件に照らすと、現在は実機検証と不足APIの補完が必要な段階です。

Windowsクライアントとユーザー登録ツールは旧試作のままであり、新しいAPI・ドメインモデルに合わせた刷新には未着手です。サーマル印刷と本番運用の自動化も計画段階です。

## 2. 実装済み

### Web API

- JWTによるログイン
- 最初の管理ユーザー1名の登録
- 商品の登録、一覧、詳細取得、名称・JANコード検索
- 商品名、JANコード、単位、補充基準の編集
- JAN-8、JAN-13のチェックディジット検証
- 保管場所の登録と一覧取得
- 保管場所・期限別の入庫
- 期限の近いロットを優先するFEFO消費
- 期限の近いロットを優先する廃棄
- ロットの実数に合わせる棚卸調整
- 現在庫と在庫移動履歴の取得
- 入庫・消費コマンドの冪等性
- 補充点からの買い物候補生成
- 買い物項目の手動追加、数量・購入状態更新、リスト完了
- 完了した買い物リストの購入済み商品を保管場所・期限別の実在庫へ一括入庫
- ダッシュボード集計と最大20件のページング
- Problem Details形式のエラー応答
- EF Core MigrationとPostgreSQL対応
- Liveness、Readinessエンドポイント
- Docker Compose、Caddyによる本番配備構成

### スマートフォンPWA

- ログインと初回ユーザー登録
- ダッシュボード
- 商品登録と在庫検索
- 入庫・消費操作
- 買い物リストの表示、追加、候補生成、購入状態更新
- レスポンシブ表示
- Web App ManifestとService Worker
- IndexedDBを使った入庫・消費コマンドの再送キュー
- 再送時の冪等性キー維持

### 自動テスト

2026-08-29時点で、`WebAPI.Tests`の自動テスト17件はすべて成功しています。

主な検証対象:

- JANコード検証
- 同じ冪等性キーによる入庫の重複防止
- FEFO順の消費
- 在庫不足時に在庫を変更しないこと
- HTTP APIによる商品登録、入庫、消費、履歴、買い物候補生成の一連の操作
- 買い物完了からの一括入庫と、再送時・再変換時の二重計上防止
- ダッシュボード一覧のページサイズ制限

HTTP統合テストではSQLiteのインメモリDBを使用しています。PostgreSQL固有の挙動を含む統合試験はまだありません。

## 5. 次の作業計画

### 優先度1: Phase 2の受け入れ完了

1. スマートフォン実機で画面表示と主要操作を確認する。
2. PWAのインストールとホーム画面からの起動を確認する。
3. オフラインで入庫・消費を実行し、再接続後に一度だけ反映されることを確認する。
4. iOS SafariとAndroid Chromeで問題を記録し、操作性を調整する。
5. 結果を実機確認チェックリストとして残す。

完了条件: 日常の登録、入庫、消費、買い物操作をスマートフォンだけで安定して実行できる。

### 優先度2: APIのMVP不足を補完

1. 訂正・取消を逆仕訳として記録する方式を設計・実装する。
2. 各機能のサービス層テストとHTTP統合テストを追加する。
3. APIガイドとロードマップを実装結果に合わせて更新する。

完了条件: READMEに記載された在庫管理MVPをAPIとPWAから再現できる。

### 優先度3: 本番公開前の安全性と運用基盤

1. 初回セットアップを一時トークンまたはローカル接続に限定する。
2. ログインのレート制限を追加する。
3. アクセストークンと更新トークンの運用を実装する。
4. PostgreSQLを使用する統合テストを追加する。
5. バックアップを取得し、別環境への復元を試験する。
6. HTTPS、公開ポート、ログ、ヘルスチェックを配備環境で確認する。

完了条件: 外部アクセス可能な環境へ安全に配備でき、障害時にDBを復元できる。

### 優先度4: Phase 3 Windowsクライアント

1. .NET 8 WPFの新プロジェクト構成を作成する。
2. APIクライアント、JWT認証、安全なトークン保管を実装する。
3. デバイスなしで検証できる疑似スキャナを実装する。
4. USB-HID入力の連続スキャンと入庫処理を実装する。
5. 棚卸、一覧フィルタ、CSV出力を実装する。
6. 50件連続登録の安定性を検証する。

完了条件: 50件の連続登録と棚卸を安定して実行できる。

### 優先度5: Phase 4以降
