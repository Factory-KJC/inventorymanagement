# プロダクト構想

## 1. 解決する問題

家庭の在庫管理で重要なのは正確な台帳を作ることではなく、買い物の直前に「買う必要がある物」を迷わず判断できることです。そのため入力負担を在庫精度より優先し、よく使う操作は1〜2アクションで終わるようにします。

## 2. 利用者と利用場面

初期版は単一世帯を対象にします。家族は同じ世帯データを共有し、誰が変更したかだけを履歴に残します。

| 場面 | 端末 | 主な操作 |
|---|---|---|
| 帰宅・収納 | Windows + スキャナ | 連続スキャン、数量・期限・保管場所の登録 |
| 日常の消費 | スマートフォン | 商品検索、ワンタップ消費、使い切り |
| 買い物前・店内 | スマートフォン | 自動提案の確認、手動追加、購入済みチェック |
| 棚卸 | Windows | 一覧編集、差異調整、CSV出力 |
| 紙で持ち出す | Windows + プリンタ | 買い物リストの印刷 |

## 3. コアユースケース

### UC-01 入庫する

JANコードを読み取り、既知の商品なら数量だけを追加します。期限管理品は期限を入力し、同一商品でも期限ごとに別ロットとして保持します。未知のJANコードは商品登録へ誘導します。

### UC-02 消費・廃棄する

原則として期限が近いロットから減らします。利用者がロットを指定することもできます。数量を直接上書きせず、消費または廃棄の履歴を追加します。

### UC-03 棚卸する

実数との差を「棚卸調整」として記録します。過去の履歴は変更せず、訂正履歴によって現在庫を合わせます。

### UC-04 買い物リストを作る

現在庫が補充点を下回った商品について、`目標在庫 - 現在庫` を提案数量とします。手動項目も同じリストへ追加できます。提案は利用者が却下・数量変更できます。

### UC-05 購入を入庫へつなげる

購入済み項目は未処理のまま消さず、帰宅後にまとめて入庫できます。購入と入庫を分けることで、店内操作に期限・保管場所入力を要求しません。

## 4. 業務ルール

- 数量は0以上。負在庫は許可しない
- JANコードは文字列として保持し、先頭ゼロを失わない
- 同じJANコードは同一世帯内で一意
- 期限はロット単位。商品マスタには持たせない
- 現在庫は有効な入出庫履歴の合計から導出する
- 履歴は物理削除せず、取消イベントで訂正する
- 補充点・目標在庫は商品単位。未設定の商品は自動提案しない
- 日時はDBでUTC保存し、画面では利用者のタイムゾーンで表示する

## 5. MVP対象

商品、カテゴリ、保管場所、ロット在庫、入出庫、期限表示、買い物リスト、ログイン、スキャン入力、サーマル印刷を対象とします。

初期版では、店舗価格比較、レシピ連携、画像認識、外部商品データベース自動登録、通知プッシュ、複数世帯所属は対象外です。

## 6. 成功指標

- 日常の消費登録が中央値5秒以内
- 既知商品のスキャン入庫が1件10秒以内
- 買い物後の「家に同じ物があった」件数が導入前より減る
- 主要操作で手入力する項目が最大3つ以内
